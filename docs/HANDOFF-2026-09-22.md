## 1. What this project is, in one paragraph

A consumer marketplace for Nairobi: browse merchants across 21 verticals, order food and
groceries, book spa/transport/experiences, with onboarding flows for merchants, couriers and
hosts. React 19 + Vite + Tailwind v4 serving a single Express API on one port, backed by
PostgreSQL 15. The full catalogue is **generated**, not authored: **640 merchants, 6000 items,
128 subcategories**, produced by a script into `src/db/seed_excel.sql`.

## 2. READ THIS BEFORE TOUCHING ANYTHING — six traps that have already cost real time

These are not style preferences. Each one has caused a wrong answer, a wasted hour, or a
silent failure in this project.

### 2.1 A green gate is not working software

`tsc` reported a clean build while **add-to-cart was dead on five pages**. The cause: `@types/react`
was not installed, so tsc inferred React's types from JavaScript and the errors vanished.
Installing the types exposed **19 live defects** in one run.

**Never remove `@types/react` or `@types/react-dom`.** And do not treat "tsc passes" as evidence
the feature works.

### 2.2 A clean scan is not evidence unless a known-bad input fails in the same run

The Impeccable detector timed out on every URL scan, **exited 0, and printed `[]`**. A failed scan
was byte-identical to a clean one, and 22 such "clean" results were reported as a pass. Everything
downstream of that was wrong.

**Always run a control.**

### 2.3 The build strips the live-mode injection; the dev server does not

`index.html` carries a block pointing at `localhost:8400` for Impeccable live mode. The build
removes it, so production is clean. **But a file added to `public/` while the dev server runs is
not served** — Vite indexes that directory at startup, and the new path returns the **SPA fallback
with status 200**. It looks like success. This has broken fonts twice.

**After adding anything to `public/`, restart the dev server.**

### 2.4 `skip-worktree` hides changes from git AND from `git archive`

`index.html` had the `S` flag. A rebrand edit lived only in the working copy, was never committed,
and **every deploy shipped stale HTML** while all gates stayed green. The live title still read
"NEXG Concierge" after a deploy that reported success.

**Check `git ls-files -v <file>` whenever a deploy ships the wrong content but the source looks right.**
Fixed now — the flag is removed and `index.html` is tracked normally.

### 2.5 PowerShell 5.1 will corrupt, mangle, or mislead you

Three distinct failures, all encountered:

- **`>` redirection re-encodes binary as UTF-16.** Streaming a tar through `pwsh >` produced
  `FF FE 1F 00` (a BOM) instead of `1F 8B 08` and inflated 63 MB to 120 MB. **Use `cmd /c "... > file"`**
  for binary.
- **`Out-File`/`Set-Content` are not UTF-8.** Use `[System.IO.File]::WriteAllText($p, $t, (New-Object System.Text.UTF8Encoding($false)))`.
- **It eats quotes and backticks.** A `-m` commit message containing `→` or nested quotes dies with
  `error: unknown switch`. **Write the message to a file and use `git commit -F`.**
- **Its console renders valid UTF-8 as mojibake**, which has twice looked like file corruption.
  **Verify at byte level**, never from the terminal.

### 2.6 Node 24 runs server TypeScript in STRIP-ONLY mode

`node server/index.ts` erases types but **cannot transform syntax**. Constructor parameter
properties, `enum`, `namespace` and decorators throw `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX` **at
import time and kill the process**. This actually happened with `logger.ts`.

**`tsc --noEmit` will happily pass on code that cannot run.** After any change to `server/`, run
`node server/index.ts` and confirm it boots.

## 4. Deployment — the exact procedure

Full detail in `docs/DEPLOY-STEP-BY-STEP.md`. The short version:

```bash
# 1. commit locally
git add -A && git commit -F msgfile.txt

# 2. archive TRACKED files only, transfer, extract
git archive --format=tar.gz -o /tmp/nexg.tar.gz HEAD
scp -i ~/.ssh/nexg_deploy /tmp/nexg.tar.gz root@212.95.32.229:/tmp/nexg.tar.gz

# 3. on the server
cd /var/www/apps/projects/nexg-concierge
cp .env /tmp/nexg-prod.env          # PRESERVE: holds AUTH_SECRET + DATABASE_URL
tar xzf /tmp/nexg.tar.gz -C . --overwrite
cp /tmp/nexg-prod.env .env && chmod 600 .env
docker compose build && docker compose up -d app
docker compose ps                   # expect (healthy)
curl -sS -H 'Host: nexgapp.com' http://127.0.0.1/api/health
```

agree. Setting one and not the other was a bug that cost a verification round.

## 5. Open work, in priority order

### 5.1 HTTPS — blocked on a Cloudflare permission

The site is served over HTTPS to visitors, but **Cloudflare talks to the origin over plain HTTP**
("Flexible" SSL mode). The padlock is real for the browser leg only; the origin leg is unencrypted.

The human tried to create an Origin Certificate and got:

```
Failed to validate requested hostname *.nexgapp.com:
This zone is either not part of your account, or you do not have access to it.
```

**That is an account-permissions problem, not a mistake.** Two routes:

- **A — get access.** Zone owner grants SSL/TLS → Edit, or issues the cert and sends it.
- **B — skip Cloudflare (recommended).** Install `certbot`, have the human flip the DNS record
  from Proxied to **DNS only** for a few minutes, run an HTTP-01 challenge, install the cert, add
  a 443 block, then flip back to Proxied and set SSL mode to **Full (strict)**.

Route B needs no Cloudflare dashboard access at all. `Strict-Transport-Security` is already written
in `server/security.ts` and activates automatically when `NODE_ENV=production`.

### 5.2 The Wolt mobile treatment — NOT finished

The human shared Wolt screenshots and has asked repeatedly. **Be honest about what is done:**

**Done:** emoji on both rails (22 of 23 tabs, verified at 360px and 1440px), the drawer now closes
and unlocks the body, nav/hamburger handover at `sm`, clipped card titles fixed, a docked search
bar with react-spring.

**Not done, and it is the visible gap:**

1. **Image tiles, not pill chips.** Wolt's rail is rounded *squares with full-bleed photography*
   and the label underneath. Ours is pills with emoji. The emoji helped; it is not the same object.
   `sanity`: `src/data/categoryCatalog21.ts` has `image` and `heroImage` fields — **check whether
   they hold real URLs before relying on them**, because `icon_name` looked populated and was not.
2. **Merchant card rhythm** — Wolt uses a dashed divider and a specific meta row spacing.
3. **Product-row category tab strip** on the merchant page (sticky, scrolls to section).
4. **Secondary-text contrast on dark.** The teal-on-near-black in the screenshots is genuinely low
   contrast. **Measure it, do not eyeball it.**

## 7. Impeccable live mode — what works and what does not

The human uses this to make element-by-element design changes. It is fragile in this codebase.

**To start it:**
```bash
"$USERPROFILE/.agents/skills/impeccable/scripts/impeccable.cmd" live-poll
```
Both `agentPolling` **and** `connectedClients` must be true. `connectedClients: 0` means the
browser tab must be refreshed.

**`live-poll` blocks for 600s and exits after one event.** Piping or wrapping it destroys that.
Use `--stream` for incremental delivery, or a loop that restarts it.

**Three confirmed scaffold failures — it will die on these, and it is the tool, not the caller:**

1. **`Hero.tsx`** — the scaffold searches `App.tsx` for the hero heading and cannot find it
2. **Rotating words** — rendered from `{pod.lead}`, so the text is not literal in source
   (`element_ambiguous`)
3. **`hero-wipe` classes** — built from a template literal, so there is no literal string to match

**A lease that is never answered blocks the whole queue and leaves the browser on a spinner.**
Clear it with `live-complete --id <id> --error "..."`.

**Anything literal** — buttons, cards, nav, plain text — works.

## 8. Verification standard this project expects

The human has been burned by instruments that lie, and correctly does not accept claims without
evidence. Three rules:

1. **Run a control.** A clean result means nothing unless a known-bad input fails in the same run.
2. **Measure, do not eyeball.** Sizes, contrast, positions and counts all get a number. Several bugs
   here were invisible until something was measured — the clipped card title was 40px against 77px
   of content.
3. **Report what is not verified.** "Not run" and "failed" are different answers, and both are
   better than an implied pass.

**Instrument traps already hit, so you do not repeat them:**

- A canvas returns **opaque black** for `oklch()`, which it cannot parse. Two colour probes gave
  confidently wrong results because of this. **Read raw computed values instead.**
- `window.scrollTo` reports `scrollY: 0` when a search input holds focus. **Use `mouse.wheel`.**
- `height / line-height` is not a line count. **Use `Range.getClientRects()`.**
- Screenshots taken mid-animation understate contrast.
- The dev server returning **200 with SPA HTML** for a missing asset is indistinguishable from
  success unless you check the content type.

## 9. What must be kept

- **Do not remove `@types/react` / `@types/react-dom`.**
- **Do not re-add `skip-worktree` to `index.html`.**
- **Do not commit credentials.** `logs/deploy/*` were redacted; verify before adding more.
- **Do not run `docker compose down -v`.** It deletes the catalogue volume.
- **Do not touch ports 5432 or 8080** — another platform runs there.
- **Do not raise heading `font-weight` above 700.** Quicksand's axis stops there and anything higher
  renders **synthetic** bold, which smears the counters and reads lighter, not heavier.
- **One animation library per component subtree.** Motion and react-spring both write `transform`;
  two writers on one node means the last one wins. See `docs/ANIMATION.md`.
